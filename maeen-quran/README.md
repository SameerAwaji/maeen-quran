# منصة حلقات القرآن · مَعين

نسخة الموقع المستقل من منصة متابعة حلقات القرآن الكريم، جاهزة للنشر على سب دومين لموقع مَعين، مثل
`quran.maeen.com.sa`.

| الجزء | الأداة | التكلفة في البداية |
|---|---|---|
| الواجهة (الموقع) | Vercel | مجاني |
| قاعدة البيانات، الدخول، الملفات | Supabase | مجاني (الخطة المجانية تكفي مئات الطلاب) |
| السب دومين | DNS دومين maeen.com.sa | مجاني |
| إيميلات التأكيد واستعادة كلمة المرور | Brevo أو Resend | مجاني حتى عدد كبير يومياً |

---

## محتوى المشروع

```
public/            ← الموقع نفسه (ينشر كما هو، بدون بناء)
  index.html       ← الصفحة والتصميم والخطوط المدمجة
  app.js           ← كود المنصة
  config.js        ← رابط Supabase ومفتاحه (تعبّئه أنت)
  quran.json       ← نص المصحف (رواية حفص، الرسم العثماني)
  vendor/          ← مكتبات Supabase و Excel و PDF (محلية، لا تُحمَّل من الإنترنت)
supabase/
  schema.sql       ← الجداول + قواعد الحماية + سجل التعديلات + التخزين
  functions/create-account/index.ts ← إنشاء حسابات الطلاب بواسطة المعلم
vercel.json        ← إعدادات النشر ورؤوس الحماية (CSP, HSTS…)
```

---

## خطوات النشر

### 1) إنشاء قاعدة البيانات في Supabase
1. ادخل [supabase.com](https://supabase.com) وأنشئ حساباً، ثم **New project**.
   - اسم المشروع: `maeen-quran`
   - كلمة مرور قاعدة البيانات: قوية واحفظها في مكان آمن.
   - المنطقة: اختر الأقرب للسعودية من القائمة المتاحة.
2. من القائمة الجانبية: **SQL Editor** ← **New query** ← الصق محتوى `supabase/schema.sql` كاملاً ← **Run**.
   يجب أن تنتهي بدون أخطاء. (الملف آمن لإعادة التشغيل إذا احتجت.)

### 2) إعدادات الدخول (Authentication)
1. **Authentication ← Sign In / Providers ← Email**: تأكد أنه مفعّل، و **Confirm email** مفعّل.
2. **Authentication ← URL Configuration**:
   - **Site URL**: `https://quran.maeen.com.sa` (أو السب دومين الذي تختاره)
   - **Redirect URLs**: أضف نفس الرابط.
3. **Authentication ← Policies/Passwords**: اجعل أقل طول لكلمة المرور 8.
4. **بريد الإرسال (مهم)**: بريد Supabase الافتراضي يرسل عدداً قليلاً جداً في الساعة.
   أنشئ حساباً مجانياً في [Brevo](https://www.brevo.com) أو [Resend](https://resend.com)، ثم
   **Project Settings ← Authentication ← SMTP Settings** وأدخل بيانات SMTP منهم،
   واجعل المرسل مثل `no-reply@maeen.com.sa` (يتطلب إضافة سجلات تحقق في DNS يعطيك إياها المزوّد).
5. (اختياري) **Authentication ← Email Templates**: عرّب نصوص رسائل التأكيد واستعادة كلمة المرور.

### 3) ربط الموقع بقاعدة البيانات
من **Project Settings ← API** انسخ:
- **Project URL**
- مفتاح **anon public**

وضعهما في `public/config.js`:
```js
window.APP_CONFIG = {
  supabaseUrl: "https://xxxxxxxx.supabase.co",
  supabaseAnonKey: "eyJhbGciOi..."
};
```
> ⚠️ لا تضع أبداً مفتاح `service_role` في الموقع.

### 4) النشر على Vercel
**الطريقة الأسهل (من الكمبيوتر):**
```bash
npm i -g vercel
cd maeen-quran
vercel deploy --prod
```
اختر إنشاء مشروع جديد، واقبل الإعدادات الافتراضية (لا يوجد أمر بناء).

**أو عبر GitHub:** ارفع المجلد إلى مستودع خاص، ثم في Vercel: **Add New ← Project ← Import**، بدون أي إعدادات بناء.

### 5) السب دومين
1. في Vercel: **Project ← Settings ← Domains ← Add** واكتب `quran.maeen.com.sa`.
2. Vercel يعطيك سجلاً مثل:
   ```
   النوع: CNAME    الاسم: quran    القيمة: cname.vercel-dns.com
   ```
3. أضفه في لوحة DNS لدومين `maeen.com.sa` (عند الجهة التي تدير الدومين). خلال دقائق إلى ساعات يعمل،
   ويصدر Vercel شهادة HTTPS تلقائياً.

### 6) دالة إنشاء حسابات الطلاب (للطلاب بدون إيميل)
تسمح للمعلم بإنشاء حساب دخول للطالب باسم مستخدم وكلمة مرور، وبتعيين كلمة مرور جديدة له.
1. في Supabase: **Edge Functions ← Deploy a new function ← Via Editor**.
2. اسم الدالة: `create-account` (بالضبط).
3. الصق محتوى `supabase/functions/create-account/index.ts` ثم **Deploy**. اترك خيار **Verify JWT** مفعّلاً.
4. (اختياري) **Edge Functions ← Secrets**: أضف `ACCOUNT_EMAIL_DOMAIN` بقيمة `s.maeen.com.sa`
   (هي القيمة الافتراضية أصلاً)، وأضف `ALLOWED_ORIGIN` بقيمة `https://quran.maeen.com.sa` لقصر الاستدعاء على موقعك.
5. تأكد أن `usernameDomain` في `public/config.js` بنفس القيمة.

**كيف يعمل؟**
- من صفحة الطالب: **«إنشاء حساب دخول»**، أو عند **إضافة طالب** فعّل «إنشاء حساب دخول للطالب الآن».
- يكتب المعلم اسم مستخدم إنجليزياً (مثل `ahmad.salem`) وتُولَّد كلمة مرور عشوائية، ثم تظهر بيانات الدخول
  مع زر **إرسال لولي الأمر بواتساب**.
- الطالب يدخل من نفس صفحة الدخول بكتابة **اسم المستخدم** بدل الإيميل.
- إذا نسيها: المعلم يضغط **«كلمة مرور جديدة»** من صفحة الطالب.
- الدالة تتحقق من هوية المعلم وصلاحية «إضافة الطلاب وتعديل بياناتهم» وأن الطالب داخل نطاقه، وتعمل بمفتاح
  الخدمة على الخادم فقط. حسابات بقية الأدوار (معلم، ولي أمر…) ينشئها من يملك «إدارة الأعضاء».
- `s.maeen.com.sa` نطاق داخلي لأسماء المستخدمين فقط، لا تُرسل إليه أي رسائل ولا يحتاج إعداداً في DNS.

### 7) أول تشغيل
1. افتح الموقع وأنشئ حسابك (الإيميل، الجوال، كلمة المرور)، وأكّد الإيميل.
2. **أول من يسجّل يصبح مدير البرنامج** تلقائياً. بعدها لا يستطيع أحد آخر أن يسجّل مديراً.
3. لنقل بياناتك من المنصة التجريبية: في المنصة القديمة **الإدارة ← تنزيل نسخة احتياطية**، ثم في الموقع الجديد
   **الإدارة ← استيراد نسخة احتياطية**. السجلات تُنقل بدون حسابات، وعند تسجيل كل معلم أو طالب
   تعتمده وتختار **«ربط بسجل موجود»** ليحتفظ بسجله.
4. أرسل رابط الموقع للمعلمين والطلاب وأولياء الأمور ليسجّلوا، واعتمدهم من **الإدارة**.

## الحماية — ما الذي يحمي البيانات؟

**على مستوى الخادم (لا يمكن تجاوزه من المتصفح):**
- **Row Level Security** على كل جدول: كل طلب يُفحص في قاعدة البيانات نفسها حسب دور المستخدم
  وصلاحياته ونطاقه (كل الطلاب / حلقاته / طلابه فقط) ونطاق التحضير. نفس جدول الصلاحيات في الواجهة
  يُقرأ من قاعدة البيانات.
- **الملاحظات منفصلة**: ملاحظة ولي الأمر لا يقرؤها الطالب، والملاحظة الداخلية لا يقرؤها إلا من يملك صلاحيتها.
- **حماية الحقول**: الطالب يستطيع فقط تعليم مهمته «منجزة»، ولا يستطيع أحد تغيير دوره أو صلاحياته بنفسه،
  والتسجيل الذاتي يبدأ دائماً «بانتظار الاعتماد».
- **لوحة الشرف** للطلاب تُحسب في الخادم وتعرض الأسماء والنقاط فقط.
- **سجل التعديلات** (`audit_log`): كل إضافة وتعديل وحذف مع صاحبه ووقته، لا يقرؤه إلا مدير البرنامج.
- **الملفات** (التسجيلات الصوتية والمرفقات) في مخزن خاص غير عام، بروابط موقّعة لا يمكن تخمينها، وحد 20 ميجابايت.

**على مستوى الموقع:**
- HTTPS إجباري (HSTS)، وسياسة أمان المحتوى (CSP) تمنع تحميل أي سكربت من خارج الموقع،
  ومنع تضمين الموقع في صفحات أخرى (حماية من التصيّد)، وكل المكتبات مستضافة محلياً.
- كلمات المرور تُحفظ مشفّرة (bcrypt) لدى Supabase، ومحاولات الدخول المتكررة محدودة تلقائياً.

**توصيات تشغيلية:**
- فعّل **التحقق الثنائي (MFA)** على حسابك في Supabase و Vercel ومزوّد الدومين.
- نزّل **نسخة احتياطية** من الإدارة أسبوعياً. (الخطة المجانية في Supabase لا تحفظ نسخاً يومية تلقائية؛
  خطة Pro تضيفها.)
- الخطة المجانية في Supabase **توقف المشروع مؤقتاً إذا لم يُستخدم أسبوعاً**؛ مع الاستخدام اليومي لا يحدث،
  وعند الإيقاف يُعاد تشغيله بضغطة من لوحة Supabase.
- **نظام حماية البيانات الشخصية (PDPL)**: أضف صفحة سياسة خصوصية في موقع مَعين، واحصل على موافقة
  ولي الأمر عند تسجيل الطلاب القُصّر، واحذف بيانات من يطلب ذلك (الإدارة ← حذف العضو).

## تحديث الموقع لاحقاً
عدّل الملفات في `public/` ثم أعد `vercel deploy --prod`. وإذا تغيّر `supabase/schema.sql`
شغّله مرة أخرى في SQL Editor (آمن لإعادة التشغيل).
